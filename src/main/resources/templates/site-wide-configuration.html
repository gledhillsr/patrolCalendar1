Create the self-made tables everywhere

Runs CREATE TABLE IF NOT EXISTS for menubuttons, shifttemplatepatrollers and <resort>_password_reset_tokens against every resort in PatrolData.resortMap. Safe to run more than once - a resort that already has a table is left as it is.

Once every resort reports ok, that table's create-on-first-use call can come out of its read and write paths. menubuttons and shifttemplatepatrollers have been through this; password_reset_tokens still creates itself on demand until this has run everywhere.

Both are listed even though only one is being migrated at a time: a resort added to the map later needs all of them, and this is the only place that can give it one.

Add the shift Label column, and sort the old Start values into it

A shift row now carries a Label - what the calendar shows, such as TL, dir or mentee - separately from its Start Time. The Start field was free text for twenty years, so most resorts have both real times and job names sitting in the one column.

This gives every resort the Label column, then sorts what is already there: a Start value that reads as a time stays, rewritten in one canonical form (0800, 8am and 8:00 all become 8:00); a Start value that is not a time was always a label, so it moves to the Label and the Start is emptied. End times are left exactly as they are.

Safe to press again. A resort that has already been done reports nothing to do and nothing is written. It judges by the data rather than by whether the column exists, so a resort left half-done by an interrupted run gets finished rather than skipped.

This rewrites rows in two tables, in every resort, and there is no undo. Take a database backup of shiftdefinitions and assignments before the first run.

Until a resort has been through this, the shift editors and the daily reminder cannot read its shifts - they expect the Label column.

Remove shift templates with no event name

A template row's position lives in a _<n> suffix on its name, and the template editor used to accept a blank name - writing rows called _0 that belong to no template and show as a blank entry in its dropdown. Nothing can create one any more; this clears up what was left behind.

Find first. It only reports, so it is safe to press.

Somebody who directs more than one resort appears once. This is for announcing a new feature, or telling everyone about a problem.

Everyone is selected to begin with. Deselect anybody you do not want before sending - and note the send happens in the background, so the confirmation counts who was queued, not who received it.
